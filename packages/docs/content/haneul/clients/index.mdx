A client is how your code reads from and writes to the Haneul network. There are two to choose from,
and they implement the same API (the same method names, options, and response shapes), so the choice
is about which transport suits your application, not about which features you get.

| Client                                     | Choose it for                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------- |
| [`HaneulGrpcClient`](/haneul/clients/grpc)       | The default. Reads from a full node, and the only client with real-time subscriptions |
| [`HaneulGraphQLClient`](/haneul/clients/graphql) | Reads from the indexer, and custom queries written against the GraphQL schema         |

Both are fully supported primary choices. Pick `HaneulGrpcClient` if you have no particular reason to
prefer one, and `HaneulGraphQLClient` when your application wants to query the GraphQL schema directly.
Because they share an API, moving between them is mostly a matter of changing the constructor.

<Callout type="info">
	JSON-RPC is deprecated. See the [migration guide](/haneul/migrations/haneul-2.0/json-rpc-migration) if
	you maintain existing JSON-RPC code.
</Callout>

## Quick start

```typescript
import { HaneulGrpcClient } from '@haneullabs/haneul/grpc';

const client = new HaneulGrpcClient({
	network: 'mainnet',
	baseUrl: 'http://158.69.54.239:9000',
});

const { balance } = await client.getBalance({ owner: '0x...' });

const { object } = await client.getObject({
	objectId: '0x...',
	include: { content: true },
});
```

The same code against GraphQL differs only in how the client is created:

```typescript
import { HaneulGraphQLClient } from '@haneullabs/haneul/graphql';

const client = new HaneulGraphQLClient({
	network: 'mainnet',
	url: 'https://graphql.mainnet.haneul.io/graphql',
});
```

## Three ways to call a client

Each client exposes the same functionality through three surfaces, aimed at different callers.

### Top-level methods

The main API for application code. Read data, execute transactions, and query history by calling
methods directly on the client:

```typescript
const { objects } = await client.listOwnedObjects({
	owner: '0x...',
	include: { display: true },
});

const result = await client.signAndExecuteTransaction({
	transaction,
	signer,
	include: { effects: true, balanceChanges: true },
});
```

These are documented in [Querying data](/haneul/clients/querying) and
[Signing and execution](/haneul/transactions/signing-and-execution). Where a transport can return more
than the shared shape carries, it adds options here, such as `include: { protoJson: true }` on gRPC.

### `client.core`

The transport-agnostic contract, for libraries that must work with whichever client their caller
supplies:

```typescript
import type { ClientWithCoreApi } from '@haneullabs/haneul/client';

export async function fetchResource(client: ClientWithCoreApi, objectId: string) {
	return client.core.getObject({
		objectId,
		include: { content: true },
	});
}
```

See the [Core API](/haneul/clients/core) for the contract and the cross-transport differences to
account for. Application code does not need this. Call the top-level methods instead.

### Native APIs

Each client also exposes its transport in full, for the cases the shared API does not cover:

```typescript
// gRPC: generated service clients, read masks, and streams
const { response } = await grpcClient.ledgerService.getServiceInfo({});

// GraphQL: type-safe custom queries
const result = await graphqlClient.query({
	query: graphql(`
		query {
			chainIdentifier
		}
	`),
});
```

gRPC adds [raw list RPCs](/haneul/clients/grpc#using-service-clients) and
[subscriptions](/haneul/clients/grpc#subscriptions); GraphQL adds
[custom queries](/haneul/clients/graphql#writing-queries) against the schema.

## Client extensions

Both clients support extensions through `$extend`, which lets SDKs such as
[@haneullabs/walrus](https://www.npmjs.com/package/@haneullabs/walrus) add functionality to a client your
application already configured:

```typescript
import { walrus } from '@haneullabs/walrus';

const client = new HaneulGrpcClient({ network: 'mainnet', baseUrl: '...' }).$extend(walrus());

const { blobId } = await client.walrus.writeBlob({
	blob: file,
	deletable: false,
	epochs: 3,
	signer: keypair,
});
```

See [Building SDKs](/haneul/sdk-building) for creating your own.
